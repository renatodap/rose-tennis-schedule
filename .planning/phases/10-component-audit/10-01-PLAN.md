# Phase 10-01: Audit UI Components for Hardcoded Logic

## Objective
Identify components that have hardcoded logic which should be configurable via props.

## Context
@components/ui/*.tsx - should be pure, atomic
@components/**/*.tsx - domain components may need refactoring

## Tasks

### Task 1: Audit UI primitives
- **Type:** audit
- **Files:** `components/ui/*.tsx`
- **Action:**
  1. Review each UI component (button, input, card, etc.)
  2. Ensure they are purely presentational
  3. Check they don't have hardcoded domain logic
  4. Document any violations
- **Verify:** Complete audit of UI components
- **Done:** [ ]

### Task 2: Audit dialog components
- **Type:** audit
- **Files:**
  - `components/*/Create*Dialog.tsx`
  - `components/*/Edit*Dialog.tsx`
  - `components/*/*Dialog.tsx`
- **Action:**
  1. Check for hardcoded text that should be props
  2. Check for hardcoded styles that should use constants
  3. Check for duplicated patterns across dialogs
  4. Document findings
- **Verify:** Complete audit of dialogs
- **Done:** [ ]

### Task 3: Audit list/card components
- **Type:** audit
- **Files:**
  - `components/*/*Card.tsx`
  - `components/*/*List.tsx`
- **Action:**
  1. Check for hardcoded empty states
  2. Check for hardcoded loading states
  3. Check for repeated patterns
  4. Document findings
- **Verify:** Complete audit of cards/lists
- **Done:** [ ]

## Verification
- [ ] All components audited
- [ ] Issues categorized by severity
- [ ] Refactoring plan ready

## Success Criteria
- Clear understanding of component atomicity issues
- Priority list for fixes
